# 4 · Verify: the gate

This applies the new-row gate in `research-standards.md`.
- One fresh Opus agent per check, using `briefs-verify.md`.
- Agents report; you decide and write.

| Check | Must establish |
|---|---|
| **Second pass on each Yes** | A fresh agent sees only the claim and its source, searches first, then runs the five disproof tests. Verdict: confirmed, narrowed or failed. It covers: the Oracle products; the Edge AI verdict; the offer choice (bio, hw or both) and any offer it rejected. |
| **Each signal** | Opened at its source: quote, date, open or closed, team. Regraded against the rubric, with corrected text. |
| **Facts the page will print** | Identity, HQ, sizes, programs and units, each with a dated source. Plus what the likely problem costs the business, with the arithmetic marked "(inferred)". |
| **Internal claims** | Traced to the file and slide, or to Alex's message, and credited to the speaker. Client status worded exactly as the record shows it. |
| **Titles** | Sales Navigator checked against public sources. Neutral wording where they conflict. |
| **The best hook** | The strongest current sign that AI is on the radar of the team the offer serves, per the playbook's hook rule. Also the strongest pain trigger, for the Need signals row. |

**Record the results**
- `oracle_use.cross_checked: true`, with each item's verdict in its `check`.
- For Edge AI: start `edge_ai.caveats` with "Second pass DD Mon YYYY: <verdict>.", where the page shows it.
- For the offer choice: one line in `angle_note`, e.g. "Offer second-passed DD Mon YYYY: bio confirmed; hardware no (devices partner-built)."

**Then**
- Apply every correction.
- List everything narrowed or dropped, for the report.
