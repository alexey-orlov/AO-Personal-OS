- **The plugin** (the Codex plugin in Oracle's Git repo; SoftServe has the link): an SDK / API to operate AIDP — ingest and transform data, build agents — used for demos and **for production**. Also **migration plugins** (Databricks, Snowflake, Microsoft Fabric, Informatica) and a **Fusion connector** that extracts Fusion data into AIDP and builds the bronze-to-gold pipelines; useful for PoCs and production. You prompt "load these files into AIDP" and it connects and does the rest. Alex asked whether everything is done via Codex rather than manually in AIDP → "It's all Codex"; you need architecture skills more than coding, because you sometimes have to fix things.
- **In AIDP:** data and AI in one platform; the data part sits on the **Autonomous AI Lakehouse**, Oracle's flagship lakehouse database. The master catalog holds the data; the plugin creates the bronze, silver and gold layers, and the demo files land in bronze.
- **Deep Insights:** an agent built on an **enterprise ontology** inside AIDP, extracted from several data sources; an advanced data analyst / data scientist that fits any use case — research, analysis, forecasting, recommendations. Modes: instant, thinking, pro. A good pattern to scale because both the demo and the path to production can be largely automated.
- **The run:** the scripted question "for September 2026, compare actual revenue, opex and EBITDA with budget across the Nordic region" (the FX effect), then "why is Norway 50 million below revenue plan…"; the answer carries insight and recommendations, "not just a chatbot". Actions on the underlying applications are coming.

**The sales pattern**
- **Land and expand:** land in one line of business with one use case, then expand — unlike, say, a predictive-maintenance build for a manufacturer. Similar to Databricks' Genie / ontology concept. Fast to build, even into production: an airline customer went from the executive discussion to production in **4 weeks**; the only friction was the CISO.
- Alex: as with SoftServe's enterprise customers, there is usually no meaningful use-case input at the start — you begin from the capability and the customer's Oracle data sources and propose the use case yourself? → Yes, but you must meet the business: IT contacts should connect you to it; take a **challenger approach** — research the company, bring a use case you believe they care about, to the right audience; easier than pitching bottom-up. In the first demo meeting they may redirect you to another interest, which opens the follow-up.
