## The method the skills have to encode

Alex's own procedure, reconstructed as a numbered sequence from the [07-24 sync](calls/oracle/2026-07-24_133119_one-on-one_vlad-productization-sync.md) plus his packaging workbooks ([C §3](docs/2026-09-17_packaging-skills-prep/C-vlad-feedback.md)): go/no-go gate (is there real partner pull, and is this case packageable at all — some stay opportunistic) → start from one delivered engagement, because the generalization past that customer *is* the product work → enumerate the workflow as N steps and fill three lenses per step (what the vendor pack gave · what SoftServe implemented · what stays custom per engagement) → a **separate, up-front vendor-taxonomy gap task** ("look at such-and-such vendors and highlight which steps I'm missing") → a differentiation pass across the vertical scenarios with a "what matters here" cell per step × vertical → widen the prompt deliberately → **adjudicate by hand: generation is for coverage, judgment is for truth** → interrogate every step for its failure path (no handling = an explicit OUT OF SCOPE line, never silence) → the four-axis specificity test on every feature (customer- · engine- · use-case- · industry-specific; label, don't delete) → add the cross-vertical extensions the delivered case never had → finish the table's contents → build the per-capability × phase packaging sheet on the fixed layer taxonomy → derive the external artifacts → name the skills post-factum.

## Rules that bind a generated artifact

- **Never invent a tier, a price or a proof point.** A pack with no S/M/L gets the block reframed ("What the PoC buys" — real duration, real contract value, IN / NOT IN SCOPE), not indicative ranges. Peer claims are all-or-none; "PROVEN" is reserved for delivered results. ([A1 §3.1](docs/2026-09-17_packaging-skills-prep/A1-sessions-decks-onepagers.md))
- **The one-pager is two documents, not one.** An *internal scoping* one-pager (scope prose with HITL · verticals with worked examples · the three- (now four-) lens capability matrix · IN/OUT scope · PoC process flow) and an *external sales* one-pager (name · one-liner · problem · solution as a job reframe with outcome arrows · architecture · proof strip with caveat · S/M/L with prices and timelines · why-it-sells-for-the-partner · verticals · named CTA). **A pack is complete when both exist and agree.** ([C §5](docs/2026-09-17_packaging-skills-prep/C-vlad-feedback.md))
- **The packaging tagline is not a product one-liner** — Alex rejected his own "packaged from proof of value to enterprise scale" on the mini-site, though both his one-pagers use it. A generated one-liner must state the job and the outcome in the reader's words. ([C R11a](docs/2026-09-17_packaging-skills-prep/C-vlad-feedback.md))
- **Architecture ≠ capability** — layers get visualized as layers, features get a structured list; a block that does both is wrong. ([C R11b](docs/2026-09-17_packaging-skills-prep/C-vlad-feedback.md))
- **Counted allowances with worked examples** in every open-ended tier cell ("up to 5 non-native business rules, i.e. …"; read-in / write-out marked), and scope decomposed on a **fixed delivery-layer taxonomy** (discovery · infra wiring · configuration · UI · business logic · analytics · AI pipeline · integrations · access rights · observability · roll-out · duration · pricing) so two packs are comparable. ([C R27–R28](docs/2026-09-17_packaging-skills-prep/C-vlad-feedback.md))
- **Prices come from the real signed SoWs**, services (fixed / POD) separated from client-paid consumption, with two standing caveats: the first-of-kind customer's SoW is bigger than the package because the pack was built during it, and a package framing does not bind critical feature requests. ([C R29](docs/2026-09-17_packaging-skills-prep/C-vlad-feedback.md))
- **Clearance is per-artifact and revocable** — a customer name cleared in one round was withdrawn two days later. No customer name, logo or uncleared figure in anything shipped; anything that must never ship lives outside the publish root ("unreferenced is not unshipped"). ([A2 §3c](docs/2026-09-17_packaging-skills-prep/A2-sessions-minisite-demos.md))
- **The feature table's own row rules**, from the full [07-24 row-by-row review](calls/oracle/2026-07-24_133119_one-on-one_vlad-productization-sync.md) — the stretch the partial transcript was missing, and the closest thing to a spec for the feature-list skill: rows run in **workflow order**, not table order · a feature name points at **the task being solved**, between "'Classifier' — you have to guess what classifier" and "contract header extraction", which "already implies it's a contract and that it has a header" · **never name the model in a feature** ("I wouldn't write that it's Llama — it's not a property of the feature, and why hard-wire ourselves to it") · the **custom-work column means what stays custom after the feature is finished**, not the remaining backlog (read the cell back as a sentence: "the feature is perfect, and the custom work we perform is *use a better model for classification*. Is that a true statement?") · **granularity follows where the product can extend** (upload and preprocessing split, because upload implies a future API import) · **merge steps that are conceptually the same task** and turn the surviving distinction into a real feature (header vs. body fields → configuring mandatory vs. optional parameters) · **untested is not a capability** · **status claims get verified against the delivery**, not answered from assumption · and every step gets its **nuance space enumerated** ("imagine the abstract task of any documents, we're looking for some fields: what else can there be?"), each unhandled nuance becoming a row with an empty circle.
- **Process rules:** tables before slides · red-team the candidate set · gap handling is an approval gate, not an improvisation · one structure applied identically to every pack · new slides delivered as a standalone `.pptx` on the host deck's own master · a dedicated editorial/fact-check pass at the end (the step that caught the €100K/€90K contradiction and the "PROVEN" overclaim) · support a fast single-slide path, because sometimes he has eight minutes · verify his stated counts against the file before building to them. ([A1 §3.2, §3.5](docs/2026-09-17_packaging-skills-prep/A1-sessions-decks-onepagers.md))

## The shippable bundle

- **~16 items, ~450 KB** ([D §2](docs/2026-09-17_packaging-skills-prep/D-context-inventory.md)) — the bundle is small because most of what the artifacts depended on was machine folklore, not knowledge. Load-bearing: **`softserve-deck-base.pptx`** (41 KB; without it a shipped deck skill cannot make a branded file at all, and 41 KB replaces a 26 MB OneDrive template nobody else can reach) · **`check-grammar.js`** (80 KB, 316 assertions — the only place Alex's rules exist as an executable test; **one line, `products.length !== 7`, is what rejects an eighth pack**) · the `products[]` schema slice + visual-grammar §1–5/§7 · `slide-design.md`, `client-documents.md`, `research-standards.md` · the demo playbook's 11 requirements · one reference demo (`workforce-optimization`) · a new ≤2-page engagement-context doc · a versioned 91-row roadmap extract with **minted stable ids**.
- **Stays behind:** `document-rendering.md` (machine-local — its central claim, that `soffice` is dead, is false elsewhere and would send another machine down a dead path), all 25 personal automations and 22 personal skills, the `gsheets` credential, `PROVENANCE.md` bulk, customer logos, the whole `SS-work split + packaging.xlsx`, and the superseded price sets in the old-root Word docs (they would ship as fact).
- **Delivery shape (recommended, not decided):** one standalone GitHub repo that is both the marketplace and the plugin home, internally split into **`pack-docs`** (feature list · one-pager · deck — python-pptx only, a low enough bar for a technical presales person) and **`pack-web`** (demo · listing — Node ≥ 22 + Chrome + the site repo, R&D only). An in-repo plugin loads only when the session starts at that repo's root, and the packaging work happens in *other* trees — so a marketplace install is the only shape that puts the commands where the work is. Keep the skills **flat**: Claude Code scans exactly one level deep and a nested skill is silently not discovered.
- **The three risks that actually bite:** brand fonts are licensed and absent off a managed Mac (gate on a computed FIT report, never the eye) · the customer-name / pricing deny-list exists today **only for the mini-site** and must be generalized into a linter that runs over every produced artifact · the pack ↔ use-case-map join is **free text with drift and no id**, on a map that churns weekly (ship it as a versioned data file the skill reads and names the version of, never embedded).
