## Snapshot

- **What this is:** the meta-layer over [oracle-packs](oracle-packs.md) — instead of hand-building each pack's artifacts, Alex's packaging method and his accumulated review corpus are packaged as reusable skills. Its own origin rule is the one he gave Vlad on 2026-07-24: describe post-factum the steps the analytical work actually consisted of, cluster them into 2–3 skills, and write them, so each engagement "gives birth to self-acceleration skills" ([sync](calls/oracle/2026-07-24_133119_one-on-one_vlad-productization-sync.md)).
- **Nine skills, six artifacts.** `spec` turns one delivered engagement into a signed-off `pack-spec.yaml`; `feature-list`, `deck`, `one-pager` and `exec-summary` build the documents from it; `visuals` proposes the deck's icons and photos — three candidates per slot from sources licensed for commercial use, provenance recorded per file, Alex picks; `build` runs them in order with a review pause after each; `listing` and `demo` produce the mini-site entry and an interactive walkthrough. The **standard artifact set is six** — feature list · sales deck · sales one-pager · interactive demo · mini-site listing · **executive-summary slide** (on the host deck's own master); the **demo video and the Oracle Marketplace package/listing stay part of a pack's end state but are not built by the skills**, and Vlad's internal *scoping* one-pager is not a standard artifact. The plugin names moved at build time — the 09-18 decision wrote `pack-docs` / `pack-web` — so the commands read `/oracle-packs:spec`. ([plugin README](https://github.com/alexey-orlov/Oracle-Packaging-Skills/blob/main/README.md))
- **The spine is one spec file, and its intake was rebuilt after the first real runs.** Alex's 07-24 rule (*finish the table's contents; formatting is a separate later pass*) is executed as `spec` → one `pack-spec.yaml` that every builder reads; the feature list stays the master *feature* view and the site's workflow-stage view is derived from it per pack. The 09-18 design signed off the 12 components one at a time; the first runs — Account Insights and a repair-or-replace damage-assessment case, 2026-09-22 — showed the cost: the run Alex rated best asked almost nothing and put three complete alternative pack stories side by side, the worst asked at every step. Since 0.1.14 the flow is research → Alex's call on it (≤ 4 questions) → the pack's story (name, one-liner, problem, solution, buyer) as **one comparison table** → the other seven parts drafted in one pass, each checked by a fresh-context reviewer → the whole brief as one table — **at most 12 questions per run**. ([DECISIONS](https://github.com/alexey-orlov/Oracle-Packaging-Skills/blob/main/docs/DECISIONS.md) · [CONTEXT-BUDGET](https://github.com/alexey-orlov/Oracle-Packaging-Skills/blob/main/docs/CONTEXT-BUDGET.md))
- **The deck is filled, not drawn, and one architecture model feeds three artifacts** (0.1.13–0.1.30, set off by Alex's review of the first Account Insights deck). The sales deck is built by filling the Workforce Optimization reference deck's own slides — a read-only ~15 MB exemplar in the repo — so geometry, fonts, corners, icons and the header come from the reference by construction; `lint_deck.py` checks each build against the reference before Alex sees it (header, cover hero, corners, icons on the verticals, the proof slide's four quadrants and three filled stat tiles, architecture naming and flows, type floors), and the redraw builder survives only as the legacy path. One architecture model per pack (`build_diagram.py`) is drawn three ways — the deck's slide 8, the one-pager's strip (the layout Alex prefers) and the site figure — and `check_diagram.py` fails on any drift. ([DECK-FIDELITY](https://github.com/alexey-orlov/Oracle-Packaging-Skills/blob/main/docs/DECK-FIDELITY.md))
- **Every skill runs on per-step cards under an enforced context budget** (0.1.14–0.1.17): cards of ≤ 300 words listed per step in a manifest, ≤ 6K tokens before the first message and ≤ 2K per step; the nine skills' start-up reading fell from 68 files / ~226K tokens to 27 files / ~18.4K, and the test suite runs `context_budget.py` on every manifest. Rationale and owner quotes live in `docs/DECISIONS.md`, never in the cards — the mechanism-over-prose rule of this repo's CLAUDE.md, applied. ([CONTEXT-BUDGET](https://github.com/alexey-orlov/Oracle-Packaging-Skills/blob/main/docs/CONTEXT-BUDGET.md))
- **The web plugin learns the mini-site from the site itself** (0.1.34): `listing` opens on a `site` step that finds the site's own repo (`--site`, then `ORACLE_SITE_ROOT`, then a session opened in it), pulls it, reads `site.manifest.json` and compares contract rounds — its cards were written against round 9 and the site is at 11, so the site's START-HERE outranks them. Every path, gate and publish value comes from the manifest, the site's own checker is the only gate (the ported `check-grammar.js`, which lagged it, is retired), and a copy staged in the session scratchpad publishes, so any session can publish the site.
- **Two audiences, not one** — R&D (Vlad and team) run Claude Code, have Node and Chrome and can install a plugin; SoftServe sales/presales largely do not run Claude Code at all, so for them the deliverable is the artifact ([D §5](docs/2026-09-17_packaging-skills-prep/D-context-inventory.md)). Hence the split: **`oracle-packs` needs Python (python-pptx/docx) plus Chrome for the one-pager** (a low enough bar for a technical presales person), **`oracle-packs-web`** needs Node + Chrome + a checkout of the site repo. Vlad's pilot is a **plain skills copy** before any marketplace install.
- **Editing the repo does not update the skills — this is the trap that bites.** Sessions never read the repo: they read a snapshot under `~/.claude/plugins/cache/oracle-packaging-skills/<plugin>/<version>/`, and `claude plugin update` re-copies **only when the `version` in `plugins/*/.claude-plugin/plugin.json` is higher** than the installed one — at the same version it cheerfully reports "already at the latest version" and keeps the stale snapshot (discovered 2026-09-22 after **four days of edits had reached no session**). So a release is: bump the version in **both** plugin manifests → `tools/sync-shared.sh` → `claude plugin marketplace update oracle-packaging-skills` → `claude plugin update` each plugin → **start a new session** (a running one keeps what it loaded). The snapshot is taken from the **working tree, committed or not**, so a release also ships whatever else is in flight — commit first, and check `git status` before releasing while another session is working in the repo.

## Alex's design decisions — 2026-09-18

Full table: [decisions-2026-09-18.md](docs/2026-09-17_packaging-skills-prep/decisions-2026-09-18.md). The ones that bind generated artifacts:

- **Tiers: one vocabulary everywhere — PoV Jumpstart / Integration / Scaling**; S/M/L survives only as size tags in internal tables, and print artifacts get relabelled at their next rebuild.
- **One metric set per pack**, from the customer study, with attribution varying by approval and channel (under the logo where approved, anonymized otherwise). **Two contradicting or overlapping metric sets for one pack are unacceptable.**
- **Features: Area > Category > Feature with ● available / ◐ partial / ○ roadmap** — one glyph system, ending the two incompatible ones the delivered artifacts carry.
- **Optional Oracle products are a required/optional flag per item inside the architecture stack** (required = built on it or fully relying on it; optional = a plausible additional source or destination) — the shape no delivered artifact had, plus the shared catalog it must be picked from.
- **Pack name by channel:** mini-site "Workforce Optimization" · internal exec slide "Workforce Optimization App" · external one-pager and deck "Workforce optimization" with an *Accelerator App by SoftServe* subheading if needed.
- **Every integration claim states its tier** — WfO: file export/import at PoV, API integration at Integration tier (which is why the one-pager and the feature list are both right).
- **One A4 page for the sales one-pager, always** — the skill pushes back and proposes cuts rather than spilling to a second page. **Contacts as today:** one-pager and deck → Karsten (`ktram@`), mini-site → `oracle@softserveinc.com` with Karsten named, internal deck → the packager plus `RnDrequest@`.
- **The July WfO build sessions are unrecoverable** — not on this Mac, not in the cloud, not in claude.ai history; only the Jul-24 Vlad recording exists. Those learnings stay second-hand (this wiki, the call note, the July-dated reference rules). **The WfO artifacts are not being rebuilt in this project** — the goal is the skills.

## Rules the skills encode (the durable ones)

The canonical home is now `shared/references/` in the repo; the derivations stay in the prep corpus. What must not drift:

- **Never invent a tier, a price or a proof point.** A pack with no S/M/L gets the block reframed ("what the PoC buys" — real duration, real contract value, IN / NOT IN SCOPE). Peer claims are all-or-none; "PROVEN" is reserved for delivered results. **Prices come from the real signed SoWs**, services separated from client-paid consumption. ([A1 §3.1](docs/2026-09-17_packaging-skills-prep/A1-sessions-decks-onepagers.md) · [C R29](docs/2026-09-17_packaging-skills-prep/C-vlad-feedback.md))
- **Clearance is per-artifact and revocable** — a customer name cleared in one round was withdrawn two days later; nothing that must never ship lives inside the publish root ("unreferenced is not unshipped"). ([A2 §3c](docs/2026-09-17_packaging-skills-prep/A2-sessions-minisite-demos.md))
- **Feature-table row rules**, the closest thing to a spec for `feature-list`: rows in **workflow order** · a feature name points at **the task being solved** · **never name the model** · the custom-work column means what stays custom *after* the feature is finished · granularity follows where the product can extend · merge conceptually identical steps and turn the surviving distinction into a real feature · untested is not a capability · status claims get verified against the delivery · every step's nuance space gets enumerated, each unhandled nuance becoming a row with an empty circle. ([07-24 sync](calls/oracle/2026-07-24_133119_one-on-one_vlad-productization-sync.md))
- **Counted allowances with worked examples** in every open-ended tier cell, scope decomposed on a fixed delivery-layer taxonomy so two packs are comparable; **architecture ≠ capability** (layers visualized as layers, features as a structured list); a generated one-liner states the job and the outcome in the reader's words, never the packaging tagline. ([C R11, R27–R28](docs/2026-09-17_packaging-skills-prep/C-vlad-feedback.md))
- **Process:** tables before slides · red-team the candidate set · gap handling is an approval gate, not an improvisation · one structure applied identically to every pack · a dedicated editorial/fact-check pass at the end · verify stated counts against the file before building to them. ([A1 §3.2, §3.5](docs/2026-09-17_packaging-skills-prep/A1-sessions-decks-onepagers.md))
- **Model routing expressed as roles, not model names** — cheapest model for mechanical work, strongest for design and red-team calls — or the skill ships Alex's subscription shape. ([A2 §2.7](docs/2026-09-17_packaging-skills-prep/A2-sessions-minisite-demos.md))

## Brand alignment after SoftServe's 2026 rebrand (audited 2026-09-18)

- **The deck kit was already right, and that was the biggest risk.** `softserve-deck-base.pptx`'s theme names **Azurio** + **Replica LL TT** with the Lviv-blue / Austin-orange scheme; there is no teal, no Montserrat and no Open Sans anywhere in the repo, and no rounded shapes or shadows in the package. `docProps` identifies it as SoftServe's own **2026 Corporate Template** (modified 2026-07-27), which also settles a question the web spec could not: **the spark monogram is not retired** — it is the only media in SoftServe's current template. It is retired from the *web header*, not from the brand.
- **Three breaks fixed in `oracle-packs-web:listing`** (commit `b2bfa28`): the publish wrapper stripped `data-theme="dark"` by exact line and the site's page now opens `data-theme="light" data-brand="ss26"`; the skill knew nothing about sentence case, so a newly inserted product would have shipped in CAPITALS (it now says: write every string in sentence case, and never add rows to the site's one-time `content-case.js` overlay); and `assets/README.md` pointed at the skill's own fork of `check-grammar.js`, which has no brand assertions and would pass a listing the site's gate rejects.
- **Hexes deliberately left alone.** Every SoftServe colour in the kit is one channel step from the website's tokens (`1485C3`/`1485C4`, `F36949`/`F46A4A`, `26282B`/`26292B`) — but those values came out of SoftServe's *own EMEA template*, so "correcting" them to web values would make decks diverge from the master. Both sets are now recorded in `.claude/references/softserve-deck-kit.md`, with the template's true-grey ramp vs the web's blue-tinted one flagged as unresolved.
- **The trap worth knowing:** the deck base's layout defaults its title to `cap="all"` + `+mn-lt`, i.e. UPPERCASE Replica — the pre-rebrand convention. Only the base's own slide override makes it sentence-case Azurio, so every new title run has to carry `cap="none"` + `+mj-lt` explicitly.
