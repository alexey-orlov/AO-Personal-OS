### Top items to study this session

#### 1. 🔴 Run-on / overlong explanations: 13 instances

Your longest explanations chain 5–8 clauses with "so… which means… for example… and if…". The listener loses the point before you reach it. This matters most when a stakeholder is deciding yes or no, and here it cost you: Sapan said he was "getting a bit lost".

- "So like, for example, if we are talking about the strategic context and my suggestion was we currently have 1 and we can move to 2, which means, for example, so far based on the artifacts that were provided, I believe there was no such thing as a segmentation matrix, but there was some files shared with us, so Claude, some of the skills that we have, somehow structured…" → **Take strategic context: today it's flow 1; I'd move it to flow 2.** For example, you had no segmentation matrix, so our skills drafted one from your files. You'd complete it and keep it updated in Claude Code.
- "If you log for every specific feature a certain set of final artifacts that live across your systems, for example, you have a link to… and you have a specific Confluence page where you have… then yes." → **Only for narrow, direct queries.** For example, a feature's analytics dashboard or its responsibility matrix. Those can stay as links.
- "the goal was to consider specifically and in deep details the topic of what types of things live in WorkOS, what should— how we should call them, and where they should live ideally, given the options of…" → **The goal was to go through what lives in WorkOS: what to call each thing and where it should live** (the repo, Confluence, or a mix).

**Drill:** Answer first, then one example, then stop. Before a long answer, say the one-sentence version in your head. If you hear yourself say "which means, for example…", stop and restart with the conclusion.

#### 2. 🟢 Articles: 21 instances

Two opposite habits. You add *the* before product names (*the Confluence*, *the WorkOS*, *the Claude code*), which native speakers never do. You also drop *a/the* before ordinary singular nouns. Each slip is small, but at this density it's the most frequent marker of non-native speech in the call.

- "should be stored in **the** Confluence" → should be stored in Confluence
- "when **PM** is using the Claude code" → when **a PM** is using Claude Code
- "it's not **one-to-one relationship**" → it's not **a one-to-one relationship**

**Drill:** Product names take no article: Confluence, WorkOS, Claude Code, Azure DevOps. Singular countable nouns always take one: *a PM*, *a user*, *a clear decision*, *the file system*.

#### 3. 🟡 Adverb placement: 9 instances

In English, *always / really / actually / probably / either / then* go before the main verb, or after the first auxiliary. They don't go after the verb or in front of the subject.

- "It **always should** be updated" → It **should always** be updated
- "I need **always** the competitor list in hand" → I **always need** the competitor list at hand
- "we did not focus **really** in those sessions" → we **didn't really focus** in those sessions

**Drill:** Subject + (auxiliary) + ADVERB + verb. "The agent **always tends**", "it **should either** be", "I'll **then** spend", "you **probably** remember".

#### 4. 🟡 Wrong or missing preposition: 13 instances

Several verbs and nouns need a fixed preposition. *Object* is the one to fix first, because you use it to close decisions ("approve or object").

- "please approve or **object it**" → please approve or **object to it**
- "the agent has some expectations **from** the source file" → the agent has certain expectations **of** the source file
- "we did not focus … **about** whether the user needs" → we didn't focus **on** whether the user needs

**Drill:** *object **to***, *focus **on***, *dedicated **to***, *elaborate **on***, *collaborate **on***, *a question **for** someone*, ***in** Confluence*, ***in** some cases*.

#### 5. 🟡 Non-native verb-noun collocations: 8 instances

These are word pairings a native speaker wouldn't use together. The meaning gets through, but they sound foreign.

- "**induce some problems on** us" → **cause some problems for** us
- "do you **feel enough capacity**" → do you **have enough capacity**
- "we need to **set expectations clear**" → we need to **set clear expectations**

**Drill:** *cause problems for*, *have capacity*, *set clear expectations*, *keep it consistent*, *stick with a process*, *one caveat* (not *footnote*), *I mentioned that* (not *I told that*).

#### 6. 🟡 Mangled set phrases: 10 instances

These are fixed idioms. Even a one-word change makes them sound wrong.

- "how it works **behind the hood**" → how it works **under the hood**
- "**with no regards to** what we decide on Confluence" → **regardless of** what we decide on Confluence
- "I will **bring your attention**" → I'll **bring it to your attention**

**Drill:** *under the hood*, *ground truth*, *in detail*, *regardless of*, *in that regard*, *in good shape*, *half an hour later*, *at hand*.

#### 7. 🟡 Indirect-question inversion: 7 instances

Inside a larger sentence ("what…", "how…", "details about how…"), use normal statement order: subject, then verb. Question order is only for direct questions.

- "what they serve, **what are they** for" → what they serve, **what they're** for
- "different from **what should the agent** use" → different from **what the agent should** use
- "details about **how is that workflow**… integrates" → details about **how that workflow** integrates

**Drill:** "I know **what it is**" / "Tell me **how it works**" / "Here's **what the trade-off is**." A direct question does invert: "**Is it** going to be just a draft plan?"

#### 8. 🟡 False friends / RU-UA calques: 6 instances

These are Russian/Ukrainian phrases translated word for word. They're grammatical but carry the wrong meaning in English.

- "**based on our practice**" → **based on our experience** (практика ≠ *practice*)
- "a **visual schema** of the workflow" → a **workflow diagram** (схема ≠ *schema*, which is a data structure in English)
- "maybe he was **out of context**" → maybe he **didn't have the full context**

**Drill:** *experience* not *practice*, *diagram* not *schema*, *since* not *as long as* (as long as means "on the condition that"), *what to call it* not *how to call it*, *if I understand you correctly* not *if I get you correctly*.
